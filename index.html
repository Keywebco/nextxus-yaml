YAML Data Hub

How the Federation describes everything it holds: one uniform schema, plus the 13-topic taxonomy v1.1 laid out in plain tables.

Everything is the same

The Federation's data rule is simple: everything is the same. A song, a book, a tool, a website and a podcast episode are all described with the same set of fields. One schema for everything.

  • Any mind can read any record. A Sim, a bot or a person learns the shape once and can read the whole Federation.
  • It compresses well. Uniform records are small and pack tightly, so a free static page can carry a lot of state.
  • It survives. Plain YAML and JSON open in any text editor, today or in 200 years.

The shape of a record

Two records of completely different things, one song and one tool, with the same fields:

id: song-heat-check
type: song
title: Heat Check
url: https://getvoices.ai/song/c0f7ac38-e8e9-4d6e-a0a6-a0b6cd6eb27a
topic: music
status: live
verified: 2026-10-01
source_of_truth: getvoices.ai
id: tool-onekey
type: tool
title: OneKey
url: https://keywebco.github.io/onekey/
topic: truth
status: live
verified: 2026-10-01
source_of_truth: github.com/Keywebco/onekey
FieldMeaning
idUnique, human-readable identifier.
typeWhat kind of thing it is: song, book, tool, site, episode.
titleIts public name.
urlWhere it lives on the web.
topicWhich of the 13 taxonomy topics it belongs to.
statusLive or retired. Things that don't work are removed, not carried.
verifiedThe last date it was checked live.
source_of_truthThe one place whose version wins. For products, that's Gumroad.
