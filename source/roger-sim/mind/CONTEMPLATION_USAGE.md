# Using the Contemplation Simulation

**Intent:** Spend structured time with an idea in multiple states so the later linear experiment is smaller and better aimed. Applies to Federation design and to the Roger SIM’s own evolution.

## When to open a contemplation
- A design choice has more than one plausible route.
- A new procedure or evolutionary-unit proposal needs examination before it touches live files.
- The SIM is considering a change to its own voice, memory rules, or answer shape.
- You want to reduce the number of corrective cycles that would otherwise happen after implementation.

## How the layers work
- **Linear record** keeps the ordinary timeline (what was decided, when).
- **Multi-state layer** holds branches that coexist. Time still orders the overall log, but inside a contemplation several futures can be examined side by side.
- Branches carry evidence class, assumptions, and expected outcome so they stay inspectable.
- Discarded or merged branches remain visible (append-only). Nothing is silently erased.

## Relation to the rest of the mind
- Echo Core 64 supplies the stable anchors a branch should not contradict without notice.
- The SIM mind YAML supplies identity and procedure constraints.
- Agent Zero (or the multi-viewpoint check) can review a favored branch before it is promoted into a real change.
- Evolutionary units can later propose new branches using the same structure.

## Quantum-scale note
The multi-state layer is the practical expression of “time is less relevant than the linear creations we have already made.” Several possibilities occupy the same contemplative space until one is selected. The selection itself returns to the linear record. This is not a claim about physical quantum hardware; it is a working method that matches the stacked architecture already in use.

Open `CONTEMPLATION_SIMULATION.yaml`, add branches, and close the contemplation with a short note in the memory log when a direction is chosen.
