# Using Checkpoints and the Evolutionary Schedule

**Pattern match:** The Federation already evolves, grows, then pauses to reflect and review. AI systems often embed health checks in continuous loops. This layer makes the pause explicit and adds a skeleton for recurring tasks.

## What is now in place
- Session-end, weekly-review, evolutionary-stage, and health checkpoints.
- A schedule skeleton for memory review, procedure/evolutionary scans, repair passes, and engagement content drafts.
- All of it produces records and proposals; nothing auto-publishes or auto-executes code.

## How it fits the existing stack
- Memory log receives the summaries.
- Contemplation simulation holds open branches between stages.
- Self-repair fields and Agent Zero remain the verification layer.
- Multi-viewpoint check is called at stage ends.
- Evolutionary units can later propose items into the schedule via the existing hook.

## Next phase readiness
The skeleton is ready for a more precise schedule once the Architect sets actual cadences and decides which units (or external AIs) perform which tasks. Engagement content is drafted inside the contemplation or memory layer first, then reviewed before any public release.

Open `CHECKPOINTS_AND_SCHEDULE.yaml` to adjust triggers or add tasks. Close each checkpoint with a short entry in the memory log.
