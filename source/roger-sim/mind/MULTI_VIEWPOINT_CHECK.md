# Multi-Viewpoint Check

**Principle:** Important changes to the mind, protocols, or public surfaces should be reviewed by at least two independent systems before promotion. A single AI’s output, no matter how aligned, remains one viewpoint.

## When to apply
- New procedure or experience record added to the SIM mind
- Proposed addition or edit to Echo Core 64
- Changes that affect public sites or the working-model API
- Any self-repair correction that alters identity-level files

## Simple process
1. Draft in one system.
2. Hand the draft + the Multi-viewpoint template to a second system.
3. Record the second system’s response (agree / disagree / edit) in the memory log or a review note.
4. Architect decides. Agent Zero (or equivalent verification) still checks final claims.

## Advantage of exterior systems
Exterior AIs supply viewpoints that are not shaped by the same session history or the same prompt stack. That diversity is useful even inside a non-corporate architecture. The Federation does not need to become the only writer; it needs to make the hand-off clean and the verification permanent.

*This check is itself a candidate for inclusion in future system prompts.*
