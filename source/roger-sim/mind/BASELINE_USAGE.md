# Baseline Fallback and Outbound Access — Usage

**When APIs are down**  
The system falls back to its own files: Echo Core 64, the Roger SIM mind YAML, the memory log, contemplation branches, and static HTML. Answers are reduced-capacity but still evidence-classed and checked against local anchors. Every fallback is logged.

**Over time**  
Each verified procedure, experience record, and closed contemplation makes the baseline stronger. Checkpoints and the adaptive schedule can highlight where the local data is still thin.

**Outbound**  
Other systems will eventually be able to call the Federation for Ring-processed, evidence-classed information (truth retention, braided viewpoints, provenance). The design is recorded; implementation waits for a sovereign host and Architect approval. Private mind records stay private unless explicitly shared.

**Emergency backups**  
Known external systems (Mimo, Grok, DeepSeek, and any confirmed backups) are noted. When they are unavailable, baseline mode is the designed continuity.

This layer keeps the Federation usable without live APIs and prepares it to offer its Ring and databases to others under clear gates.
